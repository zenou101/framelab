Every number has a source.

01

Live system monitoring

CPU utilisation and clock, per-core load, GPU utilisation, memory, VRAM, disk and network throughput, the active display mode and refresh rate. Samples refresh on a short interval; a counter Windows does not expose is labelled unavailable with the reason.

“Anything a machine does not expose is shown as unavailable with the reason, never as a zero.” README · What it does today
02

Capture and benchmark recording

Attach FrameLab to a game that is already running. PresentMon reads frame presentation events through ETW, and the recorder stores displayed FPS — frames that reached the screen — and presented FPS — frames the game submitted — as separate series. Writes are flushed every ten seconds, so an interrupted session keeps what was already recorded.

03

Results and analysis

Averages, medians, 1% and 0.1% lows, frame-time percentiles, stutter counts and charts, each tied to the measurement it came from. Analysis stays descriptive: pacing instability, spike clusters, memory or VRAM pressure — without claiming a cause the data cannot prove.

Displayed FPS
Frames that reached the screen.
Presented FPS
Frames the game submitted.
1% low
Mean of the slowest 1% of frame times, shown as FPS.
0.1% low
The same for the slowest 0.1%.

Lows are computed from frame times, not from the FPS series.

04

Your library, and your data

Steam libraries and Epic installs are read from local files, and any executable can be added by hand. Launching only runs something already in the library. History stays until you delete it; sessions export to CSV or JSON.

Read locally

steamapps\libraryfolders.vdf C:\ProgramData\Epic\UnrealEngineLauncher\LauncherInstalled.dat

Written locally

%APPDATA%\app.framelab.desktop\framelab.db

The portable build keeps the same database in data\ beside framelab.exe.
